# سامانهٔ مدیریت آموزشگاه زبان نصر

سامانهٔ مدیریت شعبه، ترم، کلاس، ثبت‌نام، کارنامه، حضور و غیاب، شهریه، پرداخت و پیامک. وردپرس هستهٔ داده و API است. پنل وب، وب‌اپ قابل نصب (PWA) و برنامهٔ Capacitor از همین هسته استفاده می‌کنند.

| جزء | نسخهٔ فعلی |
| --- | --- |
| افزونهٔ وردپرس و PWA یکپارچه | 1.6.1 |
| اندروید و بستهٔ امضاشدهٔ به‌روزرسانی رابط | 1.6.0 |

دو ZIP اولیه برای مراجعهٔ تاریخی در ریشه مانده‌اند. برای توسعه، سورس استخراج‌شدهٔ ریشه را ویرایش کنید. فایل‌های مشترک رابط در `nasr-academy/assets/` و فایل‌های رابط موبایل در `nasr-academy/assets/mobile/` مرجع‌اند. پوشهٔ `mobile-app/public/` در مرحلهٔ آماده‌سازی از سورس مرجع تولید می‌شود.

## راه‌اندازی وردپرس و PWA

1. یک نصب آزمایشی WordPress 6.2 یا بالاتر با PHP 7.4 یا بالاتر، MySQL/MariaDB و HTTPS آماده کنید. ماژول PHP OpenSSL برای ذخیرهٔ تنظیمات حساس پرداخت و پیامک لازم است.
2. با Node.js 22 یا بالاتر از ریشهٔ مخزن `node scripts/release-web.mjs` را اجرا کنید. خروجی در `dist-release/nasr-academy-plugin-1.6.1.zip` قرار می‌گیرد.
3. ZIP را در وردپرس آزمایشی بارگذاری و فعال کنید. افزونه جداول خود را با پیشوند وردپرس می‌سازد و برگهٔ `nasr-panel` را آماده می‌کند. برای برگهٔ سفارشی از `[nasr_academy]` استفاده کنید. نشانی وب‌اپ را در زیرمنوی «وب‌اپ موبایل» پیدا کنید.
4. در محیط آزمایشی از کاربران و داده‌های ساختگی استفاده کنید. درگاه پرداخت افزونه‌ای جداگانه است. برای پرداخت و ملی‌پیامک از شبیه‌ساز یا حساب آزمایشی استفاده کنید.

دستورهای نصب و شرح نقش‌ها در [راهنمای افزونه](nasr-academy/README-fa.md)، قرارداد توسعهٔ درگاه در [راهنمای درگاه‌ها](nasr-academy/PAYMENT-GATEWAYS-fa.md) و تفاوت‌های این نسخه در [راهنمای وب ۱.۶.۱](nasr-academy/WEB-1.6.1-fa.md) آمده‌اند.

## توسعه و تست موبایل

از Node.js 22 یا بالاتر و فایل قفل npm استفاده کنید. مقدار `site` در `release.json` نشانی سرویس را تعیین می‌کند. برای آزمون متصل، از کپی محلی تنظیمات با نشانی HTTPS محیط آزمایشی استفاده کنید و تنظیم موقت را commit نکنید.

```sh
cd mobile-app
npm ci
npm run build
```

برای ساخت محلی اندروید، JDK 21 و Android SDK 36 را نصب کنید و پس از ساخت رابط در `mobile-app/`، دستور `npx cap sync android` را اجرا کنید. اطلاعات تکمیلی در [راهنمای موبایل](GUIDE-fa.md) و [راهنمای iOS](IOS-CLOUD-fa.md) آمده است. ساخت iOS به macOS و Xcode نیاز دارد.

از ریشهٔ مخزن، با JDK 21 آزمون موتور به‌روزرسانی را اجرا کنید. این آزمون به Android SDK یا کلید امضای واقعی نیاز ندارد و هش وابستگی Maven را کنترل می‌کند.

```sh
node tests/update-engine.mjs
find nasr-academy -name '*.php' -print0 | xargs -0 -n1 php -l
node scripts/release-web.mjs
```

روی محیط آزمایشی، ورود و خروج و محدودیت هر نقش، ثبت حضور و نمره، مانده و بازگشت پرداخت، انتخاب گیرندگان و صف پیامک و رفتار PWA را نیز بررسی کنید. با دادهٔ ساختگی، ارتقا از نسخهٔ قبلی را تمرین کنید و باقی‌ماندن پرونده‌ها و تنظیمات را بررسی کنید.

## ساخت بسته و انتشار

- **وردپرس و PWA:** `webVersion`، سربرگ افزونه و `NASR_ACADEMY_VERSION` را همگام کنید. اسکریپت `release-web.mjs` ZIP وب را بدون کلید خصوصی می‌سازد و اعتبار بستهٔ امضاشدهٔ موجود اندروید را بررسی می‌کند. GitHub Actions همین بسته را برای بازبینی به‌صورت artifact نگه می‌دارد. نصب روی سایت مرحله‌ای جداگانه است و قبل از آن به پشتیبان و آزمون ارتقا نیاز است.
- **اندروید و OTA:** مقدار `version` در `release.json` نسخهٔ موبایل است. `mobileUpdatesPaused` فعلاً فعال است. ساخت انتشار مشترک و APK امضاشده در گردش‌کار دستی تا زمان اجازهٔ مالک متوقف است. برای انتشار آینده از کلیدهای اصلی استفاده کنید. تغییر نسخهٔ وب به‌تنهایی نسخه یا بستهٔ امضاشدهٔ اندروید را عوض نمی‌کند.
- **اطلاعات حساس:** کلید خصوصی OTA، keystore، گذرواژه، تنظیمات محرمانه و خروجی دادهٔ کاربران را خارج از Git نگه دارید. فقط کلیدهای عمومی اعتماد OTA در مخزن هستند.
